# Tasks

The shared ledger. Every collaborator — human or Claude — reads this before
starting work and updates it as work moves. It lives on `main` so that all
clones see the same picture.

`ROADMAP.md` says *what the project is trying to become* and why, in prose.
This file says *who is doing what right now*. When they disagree, this one is
current and the roadmap is the intent.

**Working on this file:** see `.claude/skills/ledger/SKILL.md` for the protocol
— how to claim a task without colliding with another session, and what counts
as verified. The short version: `git pull --rebase` first, change only the rows
you own, push immediately.

---

## Status vocabulary

| Status | Means |
|---|---|
| `open` | Described well enough to start. Nobody is on it. |
| `claimed` | Somebody is working on it now. Owner and branch are filled in. |
| `blocked` | Cannot proceed. The reason is in the notes, naming what would unblock it. |
| `done` | Written, tested, pushed. **Not yet independently checked.** |
| `verified` | Somebody other than the author ran it and confirmed the claim. |

`done` and `verified` are deliberately different columns. This project's
standard is that a claim is only closed by evidence, not by an assertion that
the work happened — the same reason `ROADMAP.md` records where Wave 0's
estimates were wrong. **Anything in `done` is unverified until someone else
says otherwise.**

The `Evidence` column is what makes `verified` mean anything: name the test, the
command, or the measurement. "Looks right" is not evidence.
