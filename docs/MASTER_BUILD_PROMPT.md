# MASTER BUILD PROMPT — Immersive Spatial Research Intelligence System

**This is the specification, verbatim, and it is the source of truth.**

It is committed rather than remembered. A specification this size cannot be
carried reliably in anybody's head, and it certainly cannot survive a model's
context being compacted mid-session — which has already happened twice while
building against it. Working from a remembered specification loses requirements
*silently*, which is the whole problem. So the text lives here,
`docs/REQUIREMENTS.md` records what has been built against each section, and
`tests/test_requirements_ledger.py` fails the build when the two drift apart.

## How this was extracted, and the mistake that was caught doing it

The source is a `.docx`, and three properties of it are worth recording because
each is a way the text could have been corrupted on the way in without looking
corrupted.

**No paragraph carries a heading style.** All 3,317 are unstyled, so there is no
outline to recover: the section numbering is partly typed into the prose and
partly generated by Word.

**1,445 paragraphs carry Word list numbering, which means their number is not in
the text at all.** A naive text extraction drops every one with no sign that
anything is missing. 84 numbered items and 1,361 bullets were reconstructed from
`word/numbering.xml`.

**The first extraction was silently corrupt, and the error was an 85% one.** The
pattern used to pull text runs was `<w:t[^>]*>`, which also matches `<w:tabs>` —
so it ran on to the next real `</w:t>` and swallowed the intervening markup into
the prose. The result was 37,934 fragments of XML spread through 1,223 of 3,348
lines, and a word count of 92,286 against a true 13,684. It read as a plausibly
enormous document. Requiring the tag to end properly — `<w:t(?:\s[^>]*)?>` —
brings the leakage to zero, which is the check that now guards it.

## Section numbering

234 of the 236 sections carry their number in the text and are recovered
mechanically. Two do not, because Word auto-numbered them and restarted its
counter, so their generated numbers collide with a list:

  list that follows §38)
- **§187 — "EVERYTHING THROUGH THE HAND" PRINCIPLE** (its title opens with a

Both are recorded by title in the requirements ledger. The numbering is stated
as ambiguous rather than guessed at, because a ledger that silently renumbered
sections would be worse than one that admits where the source is unclear.

235. FINAL AIR INK NON-NEGOTIABLE RULES Rule 1 Drawing must never wait for AI. Rule 2 Drawing must never wait for a server round-trip. Rule 3 The visible stroke should follow the hand with the lowest technically achievable perceived latency. Rule 4 Use short-horizon prediction carefully to hide unavoidable camera/inference latency. Rule 5 Never queue stale camera frames during active interaction. Rule 6 Drawing requires deliberate engagement. Rule 7 Casual pointing must never create ink. Rule 8 Erasing requires explicit eraser intent. Rule 9 Every drawing action must be undoable. Rule 10 Original strokes must be preserved when AI interprets or beautifies them. Rule 11 Annotations on research objects must remain spatially attached. Rule 12 Graph-region drawings should resolve into data coordinates where possible. Rule 13 3D annotations must remain attached to their relevant surface. Rule 14 Hand-drawn selections must map to underlying research entities rather than only pixels. Rule 15 Gesture, voice, mouse, touch, stylus, and AI must use the same command architecture. Rule 16 Two hands may cooperate, but interaction ownership must remain deterministic. Rule 17 Hand gestures may move every appropriate Workboard object, but scientific source data must have semantic protections. Rule 18 Pseudo-haptics must enhance interaction but never be represented as literal force feedback. Rule 19 Specialized haptic hardware is an enhancement, never a dependency. Rule 20 Rendering responsiveness takes priority over background AI and analytics. Rule 21 The system must dynamically reduce nonessential visual quality before sacrificing active hand interaction. Rule 22 Every important gesture state requires visual confirmation. Rule 23 Tracking loss immediately ends active pen contact and object manipulation. Rule 24 Research sketches, hypotheses, simulations, observed measurements, and AI interpretations must remain semantically distinct. Rule 25 The ultimate goal is not: Drawing on a computer using a webcam. The ultimate goal is: A researcher reaches into their digital research environment and uses their hands as naturally as they would use a pen, ruler, pointer, eraser, modeling tool, and physical workspace, while the AI understands what those actions mean.
